# grid-ruler · 网格标尺

> 抠细节时，人和 Agent 缺的不是审美，是**同一把尺子**。
> 人看到的是网格覆盖层，Agent 拿到的是数字——两边读同一个 `scale.json`，才不会各说各的。

## 这样能解决什么

| 人说的话 | 没有尺子时 | 有尺子时（本技能的输出） |
| --- | --- | --- |
| 「这里加大一点」 | Agent 猜 4px 或 10px | `24px -> 32px（+8，即 +1 个 8 的档）` |
| 「再靠近一点」 | Agent 改 6px，还没对齐 | `48px -> 40px（-8）` |
| 「这间距合适吗」 | 「看起来还行」 | `20px 不在 8 的倍数上，最近的档是 16 或 24` |
| 「页面整体节奏对不对」 | 无从判断 | 按 8 / 32 / 128 三档报告分布 |

## 尺子（唯一真相源）

基准 **8px**，档位 `8 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96 / 128 / 160 / 192 / 256`。

| 档 | 角色 | 用途 |
| --- | --- | --- |
| 8 | 细 | 最细粒度，元素对齐用 |
| 32 | 中 | 组件内间距、栅格半格 |
| 128 | 大 | 版面分区、整屏节奏 |

定义在仓库根的 `scale.json`。浏览器扩展的 `content.js` 里的三个常量**由它生成**（`test/gen-scale.js`），
两边漂移会被检查器拦下——不要手改 `content.js` 的 `@scale:begin/@scale:end` 区间。

## 怎么用

脚本在**本技能目录**的 `scripts/grid.js`（纯 Node、零依赖、不需要装包）。执行时把
`$SKILL` 换成技能目录的绝对路径：

```bash
SKILL=/path/to/grid-ruler            # 本机：D:\agent-skills\skills\grid-ruler

# 1) 口头表达 -> 确定 px（最常用）
node "$SKILL/scripts/grid.js" nudge --from 24 --to 大一点
#    「大一点」：24px -> 32px（+8，即 +1 个 8 的档）
#    别的可选：32 / 40 / 48px

# 2) 任意值吸附到尺子
node "$SKILL/scripts/grid.js" snap 20 13 4.5
#    20 -> 16px（-4）    13 -> 16px（+3）    4.5 -> 8px（+3.5）

# 3) 检查文件里的间距是否在尺子上
node "$SKILL/scripts/grid.js" check src/app.css src/Card.tsx
#    3 个间距值，1 个不在 8 的倍数上
#      src/app.css:2 margin: 60px -> 64px（+4）

# 4) 打印档位表
node "$SKILL/scripts/grid.js" scale
```

所有子命令都支持 `--json`，给需要机器读的场景用。
（开发仓库里同一脚本位于 `bin/grid.js`，功能一致。）

## 文件构成

| 文件 | 作用 |
| --- | --- |
| `SKILL.md` | 本文件：尺子定义、命令用法、边界 |
| `scripts/grid.js` | 换算脚本，无依赖 |
| `scripts/scale.json` | **唯一真相源**：基准、档位、口头表达词表（与脚本同目录） |
| `extension/` | 浏览器扩展的完整源码（见下） |
| `extension/bookmarklet.txt` | 书签版 URL —— **给人用的最省事入口** |
| `docs/书签安装与测试.md` | 给非技术用户的逐步安装说明 + 排错表 |

脚本自足：`scripts/grid.js` + `scripts/scale.json` 复制到任何地方都能跑，按 `__dirname/scale.json` 找尺子，
缺了会明确报错而不是用默认值瞎算。扩展的 `content.js` 与它读**同一份尺子**（由 `scale.json` 生成），
所以人和 Agent 用的永远是同一把尺子。

## 顺带把扩展源码也给了（可选，但省事）

`extension/` 是这个网格工具的**浏览器扩展完整源码**，与技能同一个尺子：

| 想给人什么 | 怎么做 | 对方要付出 |
| --- | --- | --- |
| **只算数字** | 装本技能就行 | 无 |
| **还要看见网格** | 用 `extension/bookmarklet.txt` 加一个书签 | 粘一次，1 分钟 |
| **要完整扩展体验**（工具栏图标、`Alt+Shift+G`） | 加载 `extension/` 这个目录 | 开发者模式 → 加载已解压 |

给非技术用户时**优先推书签**——加载已解压那一步会让绝大多数人放弃；扩展这条只留给会的人自己走。
`docs/书签安装与测试.md` 是给他们看的说明，别口述。


## 支持的表达

会先查 `scale.json` 的 `aliases`，命中就用它的档位；没命中会报错并列出可用词，不会瞎猜。
已收录：`大一点 / 大一些 / 大很多 / 稍大 / 稍微大一点 / 小一点 / 小一些 / 小很多 / 稍小 / 稍微小一点 / 靠近一点 / 紧一点 / 紧凑一点 / 再靠近一点 / 远一点 / 松一点 / 疏一点 / 再远一点`。

## 让用户也能在页面上看见网格（书签，不用装扩展）

用户说「我想在页面上看见网格」「怎么看现在是多少」「网格怎么开」时，**按这个来**：

**不要让他装 Chrome 扩展。** 扩展要开发者模式 + 加载已解压，非技术用户走不到底，而且绕不开下载入口。
用**书签**：同一份 `content.js`，粘一个 `javascript:` 开头的书签就行，任何浏览器都能用。

引导步骤（照抄给用户，别让他看代码）：

1. 用记事本打开网格项目里的 `bookmarklet.txt`（本机默认 `D:\workspace\grid-ruler\bookmarklet.txt`），
   `Ctrl+A` 全选、`Ctrl+C` 复制——内容是 `javascript:` 开头的一长串，约 5700 字符，**这是正常的**
2. `Ctrl+Shift+B` 打开书签栏 → 书签栏空白处右键 → 添加网页 → 名称填「网格」，
   网址栏清空后粘贴那一串 → 保存
3. 打开任意网页，点一下这个书签 → 网格出现；再点一下 → 关闭

**更完整的逐步说明 + 排错表**在 `docs/书签安装与测试.md`（同仓库），有测试页
`test/demo.html`（里面有故意不落在 8 倍数上的间距，便于当场看出网格的作用）。
用户说不知道怎么操作时，把那份文档的步骤读给他，或直接让他打开那个文件照做。

**纪律**：书签内容由 `bookmarklet.txt` 从 `content.js` 生成，**不要手写、不要凭记忆复述那串 URL**，
更不要把 URL 抄进任何要公开发布的内容里（长 URL 在社区平台会被判为外链）。要数字，用下面的命令。

## 能力边界（诚实边界）

| 边界 | 说明 |
| --- | --- |
| **看不见渲染结果** | 本技能只算数、只读源码。页面上实际占了多少像素，要靠浏览器扩展（人看）或你自己读代码。**不要声称"我看了你的页面"**。 |
| **不做审美判断** | 它只说"20 不在尺子上，最近是 16 或 24"，不说哪个好看。选哪个由人和设计意图定。 |
| **不自动改代码** | `check` 只报告不修改。要改由你按报告动手，或问过用户再改。 |
| **不改动尺子** | 不允许为了迁就某个值去改 `scale.json`。尺子变了，历史判断全部失效。用户明确要求换基准时才动，并说明影响。 |
| **8 不是普适真理** | 8px 基准适合界面间距；4px 基准（物料密度更高）或 10px（部分移动端）也常见。用户的项目已有既定基准时，先问，不要覆盖。 |

## 和浏览器扩展的分工

| | 浏览器扩展（给人） | 本技能（给 Agent） |
| --- | --- | --- |
| 输入 | 当前页面的真实渲染 | 源码 / 用户的描述 |
| 输出 | 屏幕上的网格与像素刻度 | 确定的 px 数字与偏差 |
| 何时用 | 目测"这里是不是大了" | "到底大多少"、"改成多少" |

两者读同一份 `scale.json`。扩展见 `D:\workspace\grid-ruler`（Chrome MV3，`chrome://extensions` 加载已解压），
工具栏图标或 `Alt+Shift+G` 开关。
